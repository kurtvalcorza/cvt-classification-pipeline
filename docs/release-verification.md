## Automatic coverage (static and unit, every pull request)

CI installs the pinned CPU-only torch wheel and the other runtime pins, then runs:

- `ruff check src tests tools`;
- `pytest`: snapshot verification and staging against synthetic manifests, the unpinned refusals, the import boundary, input and dataset validation, BYOD directory reading, average precision, the evaluation report, the notebook parity checks, the weight-facts check, the pin tool against a fake Hub, the data module against synthetic archives and folders (member-path refusals, size bounds, digest verification, stratified splits), the strict loader against a full-size random checkpoint, the torchvision transform against the Transformers processor, `tests/test_cvt_classification_colab_review_fixes.py` (the duplicate grouping and group split checked from the pixels, the notebook's own Sections 4–13 on a small stand-in model and a synthetic original/darkened archive, the at-ceiling reading, the Section 8 rebuild and the export check, the BYOD dataset outputs and refusals, the kernel cells, the guided layer, and the worker's `google.colab` stub specs), and `tests/test_small_model.py` — a small random-weight `CvtForImageClassification` taken through `predict`, `zero_shot_evaluate`, full and frozen `finetune`, `evaluate`, `save_artifact` and `apply_artifact`;
- `tools/validate_release_assets.py`: model card 1.2 structure and front matter, the pin state across the package, the manifest and the documents, identity consistency, the weight facts, the release-status tokens, and the notebook's structure, carried modules, parity, markers, BYOD gates and location fields;
- `tools/build_notebook.py --check`.

These are source, provenance and unit checks. None of them loads the pinned checkpoint, so none of them is execution evidence.

## Supported release verification procedure

Before changing the registry status from `Candidate` to `Release-grade`:

1. confirm the snapshot is pinned (`MODEL_REVISION` is a 40-hex commit and every manifest entry has a SHA-256) and that static CI is green on the exact commit under review;
2. open that exact notebook revision in a new GPU runtime (Linux x86_64: Colab, Kaggle or Linux Jupyter) (Colab or Kaggle, Tesla T4 or similar) with **no repository checkout** and a clean model cache;
3. run the notebook top-to-bottom in **one pass with no restart** (record `restarted: false`) without editing implementation cells, with every form field at its default (`USE_BYOD_IMAGE = False`, `USE_BYOD_DATASET = False`, `PER_CLASS = 200`, `EPOCHS = 5`, `FREEZE_BACKBONE = False`);
4. verify that Section 1 reports `NOTEBOOK_SOURCE.repository_revision` equal to `metadata.dimer.generated_from.revision`, and that the installed versions equal the inline `PINS`;
5. verify that every default-path stage completes: the pinned install; the carried modules; staging of all four manifest entries and `verify_snapshot`; the sample archive download with its size and SHA-256 check; `validate_dataset`; the duplicate grouping (200 groups) and the three-way group split with its cross-split duplicate counts all 0; `validate_inputs` with the `top_k=0` rejection finding; ImageNet top-5 predictions and the `sample-sanity` report; the zero-shot baseline; the blank and noise probes; the untrained-head baseline; `finetune`; the held-out comparison with counts, 95% Wilson intervals and the computed reading; the unseen split; adapter export, reload and the tolerance check; and the five outputs in `outputs/`;
6. record the number of images per class read from the archive, the held-out accuracy and balanced accuracy of the majority-class baseline, the zero-shot mapping, the untrained head and the fine-tuned model, the unseen-split scores, the per-epoch losses, the trainable and total parameter counts, the degenerate-probe answers and the wall time in the table below. No metric value is asserted in advance: a fine-tuned score at or below the zero-shot baseline is a finding to record, not a failure by itself;
7. exercise the BYOD dataset branch once with a small directory or `.zip` of class folders (`BYOD_DATASET_PATH`) and once with an incompatible one (for example a class with a single image), and record both outcomes (REL12);
8. record the notebook Git blob id, commit, runtime (platform, GPU, Python, PyTorch, torchvision, Transformers), model identifier and revision, the sample archive's SHA-256, whether the model cache was clean, and any warning judged harmless with the reason;
9. record no access tokens or other secrets.

A known-failing default path in the supported runtime blocks release.
